---
title: store-local
description: Durable artifacts on disk with zero setup — a JSON file the writer and the dashboard share.
---

`@thinking-blocks/store-local` keeps the parts in a JSON file on disk. It's the
step between the in-memory store (gone when the process exits) and Postgres
(durable, but a database to run): zero setup, but the parts and their travelers
survive a restart. Because the data lives in a file, the writer (your app, a seed
script) and the reader (the dashboard via `tb dev`) can be **separate processes**
that simply point at the same path.

## Install

```sh
npm install @thinking-blocks/store-local
```

## Wire it up

`LocalThinkingBlockStore` takes a file path and is passed to any block as its
`store`. The store snapshots itself to disk after every write.

```ts
import {
  DEFAULT_LOCAL_STORE_PATH,
  LocalThinkingBlockStore,
} from "@thinking-blocks/store-local"
import { ThinkingBlock } from "thinking-blocks"

const store = new LocalThinkingBlockStore(DEFAULT_LOCAL_STORE_PATH)

const block = new ThinkingBlock({
  name: "summarize",
  store,
  // agent, identity, prepareCall, validators...
})
```

`DEFAULT_LOCAL_STORE_PATH` is `.thinking-blocks/store.json`, relative to the
working directory — one constant so the writer and the `tb dev` reader never
drift apart. Pass any path you like.

## Durable across processes

The point of a file-backed store is that the cache outlives the process. Run a
block once, kill the process, run it again, and the same part comes straight back
from disk with no model call — proof it's durable, not held in memory.

```ts
// first process: generates, validates, snapshots to disk
const a = await block.get({ text: "..." }) // a.source === "generated"

// a brand-new process, same store path: served from the file
const b = await block.get({ text: "..." }) // b.source === "cached"
```

## See it in the dashboard

Point [`tb dev`](/docs/cli) at the same file and the dashboard hydrates from the
snapshot — every block, part, model call, and QC result, no login, no database:

```sh
tb dev
```

When you outgrow a file — concurrent writers, real query load — swap in
[`store-postgres`](/docs/store-postgres). The block code is identical; only the
`store` you construct changes.
